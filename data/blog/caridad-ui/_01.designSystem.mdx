Caridad UI es un **Design System moderno** construido con **Web Components nativos**, pensado para desarrolladores que quieren **control real**, **seguridad por defecto** y **cero dependencias externas**. 

No es una librería más.  
Es una postura técnica.

## ¿Por qué Caridad UI?

El ecosistema frontend actual está saturado de frameworks, capas de abstracción innecesarias y dependencias que envejecen rápido. Caridad UI nace como respuesta directa a ese problema.

Sus principios son claros:

- Web Standards antes que frameworks
- Componentes encapsulados por defecto
- Seguridad en el manejo del DOM
- Accesibilidad como requisito, no como parche
- Código entendible, testeable y mantenible

## Web Components como base

Caridad UI está construido sobre **Custom Elements**, **Shadow DOM** y **ES Modules**.

Esto significa:

- Encapsulación real de estilos y lógica
- No colisiones de CSS
- Uso directo en cualquier stack (o sin stack)
- Larga vida útil del código

No dependes de React, Vue o Angular.  
Dependes del navegador.

## Seguridad por diseño

Uno de los pilares de Caridad UI es el **uso seguro del DOM**.

- `textContent` en lugar de `innerHTML`
- Atributos controlados y validados
- Evita XSS por defecto
- Tests enfocados en seguridad

La seguridad no es opcional ni posterior. Está integrada desde la arquitectura del componente.

## Un sistema para proyectos reales

Caridad UI no está pensado para demos bonitas. Está pensado para:

- Productos reales
- Proyectos artísticos
- Aplicaciones independientes
- Equipos pequeños que quieren control

Menos magia.  
Más intención.

## ¿Para quién es Caridad UI?

Caridad UI es para desarrolladores que:

- Entienden cómo funciona la web
- Valoran los estándares
- No quieren reescribir su UI cada dos años
- Prefieren código explícito sobre abstracción innecesaria

Si ese eres tú, este proyecto también es tuyo.
